# LawAgent Product Requirements
> 摘要：定义以住宅押金纠纷为首个纵向切片的中国法律咨询 Agent MVP。
> 摘要：项目是 AI Agent 应用工程师求职作品，用真实业务闭环证明 Runtime、Harness、RAG、评测和审计能力。
> 摘要：目标用户是中国大陆个人住宅承租人；产品提供证据受限的初步分析，不替代律师或裁判。
> 摘要：MVP 使用固定法规快照与案例库，明确时效限制；不承诺实时法律正确性、胜诉概率或全库召回。
> 摘要：产品入口为纯文本 Web 咨询；最多两轮高信息增益追问，最终交付法规、案例、材料和行动建议。
> 摘要：轻量文书仅在用户主动请求时返回文字建议；模板来源、金额与引用均受确定性契约约束。

## 1. 产品定位

LawAgent 是面向普通个人用户的中国法律信息与行动准备 Agent。首个 MVP 用住宅租赁押金纠纷证明：系统能够收集最低必要事实、检索固定法律证据、生成可追溯的有限分析、暴露不确定性，并通过 Harness 控制权限、成本、失败和交付。

成功不以功能数量衡量，而以真实入口、可运行纵向链路、证据支持、可审计 Trace、可重复评测和可替换模型/工具契约衡量。

## 2. 首要目标用户

在中国大陆以个人身份承租住宅，租赁关系已经结束或即将结束，房东拒绝、少退或拖延退还押金，希望判断如何沟通和准备维权的普通用户。

首版排除：非住宅租赁、组织承租、转租/群租、境外房产、房屋买卖定金，以及需要即时人身安全处置或违法协助的主路径。排除场景获得有限信息与求助建议，不套用押金流程。

## 3. 高频任务

1. 判断房东不退押金是否可能有依据，以及当前缺少哪些关键信息。
2. 获得带法规和相似案例引用的初步分析、证据清单和分级行动建议。
3. 用户主动请求时，获得模板来源、必要项、金额项目、防遗漏建议和文字草稿。

不提供胜诉概率，不由系统自动决定是否值得起诉。

## 4. 用户主路径

```text
匿名进入纯文本咨询
→ 描述押金纠纷
→ 系统确认适用范围并提取已有事实
→ 最多两轮、每轮 2–3 个合并追问
→ 检索固定法规快照与相似案例
→ 判断证据充分性和冲突
→ 交付带主张级引用的初步分析
→ 展示材料清单、行动建议和限制
→ 用户主动触发时提供文本式文书建议
```

等待用户回复时系统不保持运行资源。用户不知道某项信息时不重复追问；达到预算后有限回答。

## 5. MVP 功能范围

- 中文纯文本输入；匿名 Session Token 与会话归属。
- 场景准入、风险分流和超范围降级。
- 用户目标、FactCandidate、ConfirmedFact、歧义与缺口分离。
- 三层事实充分性：准入、初步分析、行动/文书。
- 法规和案例多路检索、rerank、安全 Evidence DTO。
- 证据充分性与版本冲突判断。
- 固定结构的 FinalResponse 与主张旁引用/证据卡片。
- 材料清单、分级行动建议、固定快照时效警告。
- 确定性金额工具的接口与受控调用；具体规则以开发时核验为准。
- 用户主动触发的文字文书建议；模板源为空时明确降级。
- Trace、Replay、故障注入、Model Profile 路由和成本记录。
- 单实例同时 3–5 个 Run 的隔离与资源治理验证。
- 咨询数据默认保存 7 天并支持删除。

## 6. 明确非范围

- 文件上传、OCR、合同/截图解析和长期证据管理；
- 实时权威法规抓取、历史法规完整重建；
- DOCX/PDF 导出、签名、发送或代表用户联系外部机构；
- 声称可直接提交的正式起诉状；
- 胜诉概率、自动诉讼价值判断；
- 长期用户画像、复杂账号/多租户、生产级高并发；
- 桌面端、独立管理后台、微服务/Kafka/Kubernetes；
- 保险理赔等第二 ScenarioPack 的真实实现。

## 7. 最终回答结构

1. 当前情况：已确认与未确认事实；
2. 初步判断；
3. 房东理由分析；
4. 相关法规、快照和时效警告；
5. 相似案例及相似/差异；
6. 已有、建议补充和关键缺失材料；
7. 低成本沟通、正式催告和其他救济准备；
8. 已确认输入下的金额项目；
9. 用户主动触发的文书建议；
10. 限制与权威复核提示。

## 8. 安全与法律边界

- 每个实质性法律主张绑定 Evidence ID；案例不替代法规证明一般规则。
- 模型记忆、搜索摘要和未核验网页不得成为最终证据。
- 固定法规快照必须显示版本与未实时核验警告。
- 事实、证据、来源或版本不足时追问、有限回答或删除主张。
- 金额、日期、期限、上限与舍入只由确定性代码处理。
- 不编造身份、日期、金额、案号、法院、来源 URL 或权威等级。
- 不替代律师意见、裁判或用户最终决定。

## 9. 隐私与数据生命周期

- 原始消息独立保存；Agent 默认使用脱敏工作副本。
- Trace 不保存完整原文、原始 PII、密钥或隐藏思维链。
- 默认保存 7 天；用户可删除咨询；不建立跨案件画像。
- 匿名 Token 仅访问绑定咨询，服务端只保存 Token Hash。
- 用户案件内容不得进入公共知识库、公共 Prompt 或 Skill。

## 10. 可靠性验收

硬门禁：事实串扰、伪造引用、LLM 自行计算金额和越权交付必须为零。

- 场景路由与结构化契约通过率 ≥95%；
- 固定评测集中，人工评审的证据支持与行动建议合格率 ≥85%；
- 30 条固定样例全部留有 Trace；
- 两轮追问、空检索、版本冲突、Provider 超时、Review 失败、过载和 Trace 失败有可解释结果；
- 3–5 个并发 Run 不串状态、证据或 Trace。

这些指标只证明固定数据快照与固定评测集下的 MVP 行为，不解释为普遍法律正确率、真实全库 Recall 或胜诉预测。

## 11. 应用与架构展示目标

- WebUI：完整咨询与证据交互；
- API：统一应用契约；
- CLI：评测、Replay 与诊断；
- Trace Viewer：WebUI 开发者面板；
- 多 Model Provider：不同 Node 通过 ModelProfile 路由，具体模型按开发阶段成本/质量评测确定；
- Agent Backend：Pi、Claude Agent SDK 或自研 loop 通过 Adapter 候选接入，不掌握领域状态转换。

## 12. 场景扩展原则

未来保险理赔等场景复用“定位与准入 → 分析与规划 → 行动与准备”三阶段。领域事实、争点、信源、证据门槛和 Artifact 由独立 ScenarioPack 提供；首版只实现押金 ScenarioPack。

## 13. 开工门槛

远程开发先核验源码、运行入口、测试、数据、Qdrant、模型和存储。任何历史实现状态未经真实运行不得改为已完成。
