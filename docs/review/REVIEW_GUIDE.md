# LawAgent Cross-Agent Review Guide
> 摘要：定义调研、方案、实现、收尾四个关键节点的独立 review。
> 摘要：优先由不同模型 review；同模型自查不能冒充跨模型交叉 review。
> 摘要：review 使用维护性、代码质量、安全、性能、AI 坏味道和法律领域 persona。
> 摘要：结论必须包含证据、影响、严重级别、位置和验证建议，不能只给风格偏好。
> 摘要：persona 负责维护相关系统文档，但文档变更仍需代码和事实证据。
> 摘要：当前仓库没有可调用的跨模型 review 脚本，此能力为待建设项。

## Review 输出格式

每条 finding：`[P0-P3] 标题`、证据/位置、失败场景、影响、建议改法、验证方式。若没有 finding，仍列出已检查范围、未检查范围和剩余风险。

## Personas

| Persona | 重点 | 主要维护文档 |
|---|---|---|
| Maintainer | 模块深度、局部性、命名、依赖、可恢复性 | 设计、编码规范 |
| Quality Engineer | 验收映射、E2E、虚假信心、回归面 | 测试指南 |
| Security & Privacy | PII、权限、注入、密钥、供应链、审计 | 设计、安全相关测试 |
| Performance Engineer | 延迟、吞吐、资源、成本、基准可信度 | 测试/性能基线 |
| AI Systems Reviewer | prompt/schema、工具权限、循环、幻觉、评测污染 | 设计、测试 |
| China Legal Domain Reviewer | 法域、时效、证据、引用、历史法和免责声明 | 需求、领域验收 |

## 节点清单

- 调研：来源是否一手/最新；本地是否已核验；指标解释是否越界。
- 方案：接口是否小而完整；状态和权限归属；失败/降级；可测试与可观测性。
- 实现：正确性缺陷优先；安全/隐私；并发与幂等；性能；重复和 AI 生成坏味道。
- 收尾：需求到测试的可追踪性；真实应用证据；文档一致性；未验证项是否披露。

## 独立性规则

review 输入应提供目标、diff、相关文档和验证结果，但不要暗示期望结论。实现者不得静默删除 finding；应修复、以证据驳回或登记为明确债务。外部模型调用必须经过用户授权并遵守代码/数据保密要求。
